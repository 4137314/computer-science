#+title: Generalized bypass and select transforms
#+summary: To speed up a late signal \(x\) that crosses a long chain to \(f\), the bypass transform adds a path that uses \(x\) only where it matters (\(f=\partial f/\partial x\cdot(\dots)\)), and the select transform computes \(f_x\) and \(f_{\bar x}\) in advance and lets \(x\) choose between them with a multiplexer; carry-skip and carry-select adders are the arithmetic instances.

* Construction
Let \(x\) arrive late and \(f\) depend on it through a long path.
- *Generalized select (Shannon)*: \(f=x\,f_x+\bar x\,f_{\bar x}\). Compute both cofactors from the early inputs, then a multiplexer driven by \(x\). The delay from \(x\) to \(f\) becomes one mux; area roughly doubles for the cone.
- *Generalized bypass*: when \(x\) propagates to an intermediate node \(g\) and then along a chain to \(f\), add a path from \(x\) straight to the end, enabled by the Boolean difference \(\partial f/\partial g\) (computed from early signals): the long path is used only when the bypass is not, which makes it [[id:false-path][false]] for timing.

* Carry instances
For a block of \(k\) bits of an adder with carry-in \(c_{in}\), propagate \(p_i=a_i\oplus b_i\), generate \(g_i=a_ib_i\):
- *carry-skip*: if \(P=\prod_i p_i=1\) the block propagates, \(c_{out}=c_{in}\); a mux selects \(c_{in}\) or the ripple carry. Ripple through the block happens only when \(P=0\), where the carry does not depend on \(c_{in}\).
- *carry-select*: compute the block sum for \(c_{in}=0\) and \(c_{in}=1\) in parallel; \(c_{in}\) selects. Delay \(O(\sqrt n)\) with blocks of growing size.

The late signal only drives the final multiplexer.

* Intuition
If you have to wait for a decision, prepare all the answers and pick one when the decision arrives.

* Pitfall
Speculation costs area and power — both cofactors switch all the time — so it is applied only to the critical inputs.
