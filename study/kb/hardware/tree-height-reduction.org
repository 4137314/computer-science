#+title: Tree height reduction
#+summary: Associativity and commutativity rebalance a chain of \(n\) identical operations into a tree of depth \(\lceil\log_2 n\rceil\), and late-arriving inputs are moved close to the output; distributivity can reduce height further at the cost of more operators.

* Method
- *Associativity + commutativity*: \(((a+b)+c)+d\), height 3, becomes \((a+b)+(c+d)\), height 2. In general a chain of \(n\) operands becomes a balanced tree of height \(\lceil\log_2 n\rceil\).
- *Arrival-time aware*: with different arrival times, combine the earliest operands first (Huffman-like); the latest signal enters the last operator, nearest to the output.
- *Distributivity*: \(a(bcd+e)\), height 4 with 2-input operators, becomes \(abcd+ae\), height 3, with one more multiplication. It trades area for height; general rule: expand when the critical input is buried inside a factor.

* Derivation
A binary operator tree of height \(h\) has at most \(2^h\) leaves, so \(n\) operands need \(h\ge\lceil\log_2 n\rceil\), and the balanced tree reaches the bound. With delay \(d\) per operator, the chain costs \((n-1)d\), the tree \(\lceil\log_2 n\rceil d\).

* Intuition
Do independent work in parallel; if you have to wait for a late signal, prepare everything else meanwhile.

* Pitfall
For floating-point arithmetic associativity does not hold exactly: rebalancing changes rounding. Hardware tools apply it only to integer and Boolean operators.
