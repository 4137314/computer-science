#+title: Multi-level logic optimization
#+summary: A Boolean network is a DAG of nodes, each a sum of products of its fan-ins; it is optimised for area (number of literals) by structural operations — decomposition, extraction, substitution, factoring, elimination — and by node simplification with don't-cares, applied iteratively by heuristic scripts.

* Method
Representation: a DAG; each internal node \(v\) has a local function \(f_v\) in sum-of-products form of its fan-ins. Cost: the total number of literals in factored form, a proxy for the area after mapping.

Operations:
- *decomposition*: split a node into simpler ones, \(f=abc+abd+\bar a\bar c\bar d\to f=xy+\bar x\bar y\) with \(x=ab\), \(y=c+d\);
- *extraction*: find a common sub-expression (a kernel) of several nodes and make it a node: \(f=(a+b)cd+e\), \(g=(a+b)\bar e\to\) \(x=a+b\), \(f=xcd+e\), \(g=x\bar e\);
- *substitution*: re-express a node with an existing node as divisor: \(f=a+bc\), \(g=a+b\to f=g(a+c)\);
- *factoring*: write a node in factored form: \(ac+ad+bc+bd\to(a+b)(c+d)\);
- *elimination* (collapsing): substitute a node into its fan-outs and delete it, when it saves little or blocks other moves;
- *simplification*: minimise each node with two-level methods using don't-cares from the network ([[id:boolean-difference][observability]], satisfiability).
A script alternates them (eliminate, simplify, extract, resubstitute) until no gain.

The extracted node \(x\) is computed once and used by both outputs.

* Intuition
Two-level logic writes every output from scratch; multi-level logic shares partial results, like a program with variables instead of one huge expression per output.

* Pitfall
Optimising literals tends to deepen the network, which costs delay. The area-optimised network is the starting point for [[id:tree-height-reduction][delay-oriented restructuring]] and timing-driven mapping.
