#+title: Logic functions as memories
#+summary: Any Boolean function of \(n\) inputs and \(m\) outputs is a truth table of \(2^n\) words of \(m\) bits: store it in a memory whose address is the input, and reading the memory evaluates the function; the decoder is a fixed AND plane of all minterms, the stored bits an OR plane.

* Construction
A ROM with \(n\) address lines and \(m\) data lines has a decoder that activates one of \(2^n\) word lines (one per minterm) and an array where each column \(j\) holds output \(f_j\). Programming the array means putting a connection (a transistor) where \(f_j(\text{minterm})=1\) — or 0, depending on the technology — and none elsewhere. The output is
\[ f_j(x)=\bigvee_{k:\ f_j(k)=1} m_k(x), \]
the canonical [[id:two-level-minimization][sum of products]], with the decoder as fixed AND plane and the array as programmable OR plane.

* Intuition
A memory does not compute, it remembers every answer. With \(n\) inputs, there are \(2^n\) answers to remember.

* Pitfall
The size grows as \(2^n\): a 32-input function would need four billion words. ROMs suit small, dense functions (and FPGA lookup tables use exactly this with \(n=4\dots6\)); functions with few product terms are cheaper as [[id:pla-pal][PLAs]].
