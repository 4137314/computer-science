#+title: Gate and wire delay models
#+summary: A gate's delay grows with the capacitance it drives: to first order \(d=d_0+k\,C_L\), an intrinsic part plus a part proportional to the load (fanout gates and wire); libraries tabulate delay and output slew against input slew and load, and wires add an RC delay.

* Model
- *Linear model*: \(d = d_0 + R_{drive}\,C_L\), with \(C_L=\sum_{\text{fanout}} C_{in} + C_{wire}\). A stronger gate (smaller \(R_{drive}\)) is bigger and loads its own driver more.
- *Table model* (standard-cell libraries): delay and output transition time \(t_{out}\) are looked up in 2-D tables indexed by input transition \(t_{in}\) and load \(C_L\), interpolating between entries; rise and fall differ.
- *Unit delay*: every gate takes 1; good for counting levels, useless for sizing.
- *Wires*: a long wire is a distributed RC line; the Elmore delay of a line of length \(\ell\) is \(\approx\tfrac12 r c\,\ell^2\): quadratic in length, so long wires are split by buffers.

Bigger gates have more intrinsic delay but a smaller slope: each wins in a range of loads.

* Worked example
An inverter with \(d=20+6\,C_L\) ps drives four inputs of 3 fF each and 8 fF of wire: \(C_L=20\) fF, \(d=140\) ps. Replacing it with an x4 inverter (\(d=40+1.5\,C_L\), input capacitance 4× larger) gives 70 ps, but its own input load grows from 3 to 12 fF, slowing the gate that drives it by \(6\cdot9=54\) ps with the x1 slope: the net gain is about 16 ps, not 70. Sizing is a chain problem, not a single-gate one.

* Intuition
A gate is a current source charging a capacitor. More capacitance, more time; more current (a bigger gate), less time.

* Pitfall
Delay depends on the load, and the load depends on what is connected later: mapping and sizing decisions interact, which is why [[id:timing-driven-mapping][timing-driven mapping]] must model loads.
