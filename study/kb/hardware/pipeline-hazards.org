#+title: Pipeline hazards
#+summary: In a five-stage pipeline (IF, ID, EX, MEM, WB) consecutive instructions overlap, so an instruction may need a result not yet written (data hazard), the next PC may be unknown (control hazard) or two stages may need the same unit (structural hazard); forwarding, stalls (bubbles) and branch prediction with flushing resolve them at some cost in CPI.

* Definition
- *Structural*: two instructions need one resource in the same cycle (a single memory for instructions and data). Fix: separate instruction and data memories, more ports.
- *Data (RAW)*: =add x1,x2,x3= then =sub x4,x1,x5=: =sub= reads =x1= in ID while =add= writes it in WB three cycles later. *Forwarding* sends the ALU result from the EX/MEM or MEM/WB register straight to the ALU input; a *load-use* hazard (=lw x1= followed by use of =x1=) still needs one stall cycle, because the data appears only after MEM.
- *Control*: the branch outcome is known in EX: the two instructions fetched after it may be wrong. Options: stall, predict not taken and flush on misprediction, dynamic prediction (branch history tables), compute the branch earlier in ID.
Performance: \(\mathrm{CPI}=1+\) stall cycles per instruction; time \(=N\cdot\mathrm{CPI}\cdot T\).

Load-use: one bubble, then the loaded value is forwarded from the end of MEM to the start of EX.

* Worked example
Program mix: 25% loads, of which 40% are followed by a dependent instruction; 15% branches, taken 60% of the time, predicted not taken with a 2-cycle penalty when taken. With forwarding:
\[ \mathrm{CPI}=1+0.25\cdot0.4\cdot1+0.15\cdot0.6\cdot2=1+0.10+0.18=1.28. \]
A non-pipelined design with the same logic takes 5 cycles of a period about 5 times longer per instruction; the pipeline speed-up is \(5/1.28\approx3.9\), not 5.

* Intuition
Overlapping instructions is an assembly line; hazards are the moments when a worker needs a part the previous worker has not finished.

* Pitfall
Forwarding paths add multiplexers to the ALU inputs, lengthening the [[id:static-timing-analysis][critical path]]; deeper pipelines make branch mispredictions more expensive, so more stages are not always faster.
