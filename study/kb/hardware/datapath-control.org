#+title: Datapath and control unit
#+summary: A processor is a datapath — register file, function unit (ALU + shifter), buses, multiplexers, memory interface — steered cycle by cycle by a control word (register addresses, mux selects, operation code, write enables) produced by a control unit that sequences instructions.

* Model
- *Register file*: \(2^m\) registers, two read ports (=A select=, =B select=) and one write port (=D select=, =write=).
- *Operand selection*: the B bus takes a register or a constant (=MB=), the D input takes the function unit or memory (=MD=).
- *Function unit*: [[id:alu-design][ALU]] and [[id:datapath-subsystems][shifter]], with status flags \(V\) (overflow), \(C\) (carry), \(N\) (negative), \(Z\) (zero).
- *Control word*: the tuple (DA, AA, BA, MB, FS, MD, RW, MW) of fields that fixes one micro-operation, e.g. \(R1\gets R2+R3\).
- *Control unit*: fetches an instruction from memory, decodes it into one control word (single-cycle) or a sequence of them (multi-cycle, an [[id:finite-state-machine][FSM]]), and updates the [[id:risc-v-datapath][program counter]] (sequential, branch, jump).
- *Memory-mapped I/O*: peripherals respond to addresses, so load and store instructions talk to devices.

* Intuition
The datapath is the kitchen, the control word the recipe line for this minute, the control unit the cook reading the recipe.

* Pitfall
Every field of the control word must be specified in every cycle, including "don't write": a forgotten write enable silently corrupts a register.
