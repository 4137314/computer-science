#+title: Technology mapping by tree covering
#+summary: The optimised network is decomposed into a subject graph of NAND2 and inverters, every library cell is described by pattern graphs in the same base, and the subject graph is covered by patterns at minimum cost; on trees, dynamic programming from the leaves gives the optimal cover in linear time.

* Method
1. *Subject graph*: decompose every node into 2-input NANDs and inverters (a canonical but not unique base).
2. *Pattern graphs*: each library gate (INV, NAND2, NAND3, AND2, AOI21, …) with its area, expressed as one or more NAND2/INV trees.
3. *Partition*: split the subject DAG into trees at multi-fanout nodes.
4. *Cover* each tree: every node must be the output of exactly one chosen match, whose inputs are outputs of other matches or leaves.

Dynamic programming on a tree: for each node \(v\) in post-order,
\[ \mathrm{cost}(v)=\min_{\text{match } m \text{ at } v}\Big(\mathrm{area}(m)+\sum_{u\in\mathrm{inputs}(m)}\mathrm{cost}(u)\Big), \]
with \(\mathrm{cost}=0\) at the leaves. Optimal cover of the tree; \(O(n\cdot p)\) for \(n\) nodes and \(p\) pattern nodes.

* Algorithm
#+CAPTION: Tree covering by dynamic programming: visit the nodes in post-order and keep, for each, the cheapest library pattern matching there plus the best covers of its inputs.
\begin{algorithmic}[1]
\Require subject tree with root $t$, patterns $P$
\ForAll{nodes $v$ in post-order}
\State $best(v)\gets\infty$
\ForAll{patterns $m\in P$ matching at $v$}
\State $c\gets \mathrm{area}(m)+\sum_{u\in\mathrm{inputs}(m)} best(u)$
\If{$c<best(v)$} \State $best(v)\gets c$; $choice(v)\gets m$ \EndIf
\EndFor
\EndFor
\State \Return cover read from $choice$, starting at $t$
\end{algorithmic}

Each candidate cover is a set of patterns tiling the tree; dynamic programming keeps the cheapest per node.

* Intuition
Mapping is tiling a floor with the tiles the library sells, paying for each tile, and computing the cheapest tiling bottom-up.

* Pitfall
Cutting the DAG into trees loses optimality at the cuts (patterns cannot span a multi-fanout point), and the result depends on the NAND2 [[id:multilevel-logic-optimization][decomposition]] chosen in step 1.
