#+title: The equals–hashCode contract
#+summary: =equals= must be an equivalence relation (reflexive, symmetric, transitive), consistent over time and false for =null=; whoever overrides it must override =hashCode= so that equal objects have equal hashes, or hash-based collections will not find them.

* Statement
For non-null references \(x,y,z\):
1. reflexive: =x.equals(x)=;
2. symmetric: =x.equals(y)= iff =y.equals(x)=;
3. transitive: =x.equals(y)= and =y.equals(z)= imply =x.equals(z)=;
4. consistent: repeated calls give the same result while the objects do not change;
5. =x.equals(null)= is false.
And =x.equals(y)= implies =x.hashCode() == y.hashCode()=. The converse is not required: unequal objects may collide.

* Derivation
A [[id:hashmap-internals][hash table]] stores an element in bucket \(h(x)\bmod m\) and, to look it up, scans only that bucket with =equals=. If two equal objects had different hashes they would land in different buckets, so =contains= on one would not find the other, and a =HashSet= would hold "duplicates". Lookup costs \(O(1)\) on average when the hash spreads the elements evenly.

* Construction
#+begin_src java
  @Override public boolean equals(Object o) {          // Object, not Point
      if (this == o) return true;
      // or: !(o instanceof Point)
      if (o == null || getClass() != o.getClass()) return false;
      Point p = (Point) o;
      return x == p.x && y == p.y;
  }
  // same fields as equals
  @Override public int hashCode() { return Objects.hash(x, y); }
#+end_src
=getClass()= makes a =Point= never equal to a =ColorPoint=; =instanceof= allows comparison with subclasses but endangers symmetry and transitivity if subclasses add fields. Which to use depends on the application.

* Intuition
=equals= says when two objects are "the same thing"; =hashCode= is a quick, coarse test that must never contradict it.

* Pitfall
Overloading =equals(Point p)= instead of overriding =equals(Object o)=: the collections call the inherited identity version (see [[id:java-dynamic-binding][the binding rule]]).
