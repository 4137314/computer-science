#+title: Generic programming
#+summary: Writing types and algorithms with types as parameters, at the highest level of abstraction that does not lose efficiency; the parameter is fixed at compile time in C++ templates and checked at compile time then erased in Java generics.

* Definition
A generic type or algorithm has one or more *type parameters*: =Stack<T>=, =swap<T>=, =sort<Iterator>=. The actual type is supplied when the generic is used. The aim is to write an algorithm once for all the types that support the operations it needs.

* Four ways to write a generic swap
1. *Overloading*: one =swap(int&, int&)=, one =swap(double&, double&)=, … — repeated code.
2. =void*= and sizes (C style): =swap(void* a, void* b, size_t n)= with =memcpy= — no type checking.
3. *Common base class* with virtual methods: works only for classes in the hierarchy, costs a virtual call.
4. *Template*:
#+begin_src c++
  template <class T>
  void my_swap(T& a, T& b) { T tmp = a; a = b; b = tmp; }
  my_swap(x, y);              // T deduced as int
  my_swap<std::string>(s, t); // T given explicitly
#+end_src
Type-safe, no repetition, no run-time cost: the compiler generates one function per type used.

* C++ and Java
| | C++ templates | Java generics |
|---+---+---|
| resolved | compile time, one instance per type | compile time, then erased |
| type arguments | any type, also values (=bitset<64>=) | reference types only |
| checks | at instantiation | at declaration (bounds) |
| run-time cost | none, code size grows | casts, one shared code |

* Intuition
Generic code says what it needs from a type (copyable, comparable, iterable) and nothing else; any type that meets the requirements works.

* Pitfall
Generic is not the same as polymorphic at run time: =vector<Shape*>= with virtual calls and =vector<T>= with templates solve different problems and are often combined.
