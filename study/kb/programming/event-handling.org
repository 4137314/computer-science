#+title: Event-driven programming and event handlers
#+summary: A GUI program does not follow a fixed sequence: it registers handlers and waits; each user action becomes an =Event= object delivered to the handlers of the target node, travelling from the stage down to the target (capturing, seen by filters) and back up (bubbling, seen by handlers).

* Model
- *Events* form a hierarchy (=MouseEvent=, =KeyEvent=, =ActionEvent=, …), each with its own attributes (position, key, source) and sub-types (=MOUSE_CLICKED=, =KEY_PRESSED=).
- A *handler* [[id:abstract-class-interface][implements]] =EventHandler<T extends Event>=, whose only method is =void handle(T e)=. It is registered on a node with =addEventHandler(type, h)= or with convenience methods =setOnAction=, =setOnMouseClicked=, =setOnKeyPressed=.
- The *target* is the node that has the keyboard focus (key events) or the topmost node under the cursor (mouse events).
- *Dispatch chain*: from the stage to the target (*capturing*, intercepted by filters registered with =addEventFilter=), then back from the target to the stage (*bubbling*, handlers). =e.consume()= stops the propagation.

* Ways to write a handler
#+begin_src java
  class Clicker implements EventHandler<ActionEvent> {          // external class
      public void handle(ActionEvent e) { System.out.println("click"); }
  }
  btn.setOnAction(new Clicker());
  // anonymous inner class
  btn.setOnAction(new EventHandler<ActionEvent>() {
      // sees the outer fields
      public void handle(ActionEvent e) { counter++; }
  });
  btn.setOnAction(e -> counter++);                              // lambda (Java 8)
#+end_src
Inner and anonymous classes can access the members of the enclosing object, which keeps state in one place and improves encapsulation.

* Intuition
Instead of asking "what next?", the program says "call me when this happens". The main loop belongs to the library.

* Pitfall
Handlers run on the single JavaFX application thread: a long computation inside one freezes the whole window. Long work goes to a background thread, and only the UI update comes back.
